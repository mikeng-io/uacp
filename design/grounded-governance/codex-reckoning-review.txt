  ## 3. Attacking the redirect

  **(a) Does the RUN-loop converge?** No guarantee — and the redirect's own evidence admits it: Codex found *different* bug classes each round because a semantic screener's coverage is not monotone. What makes "run until clean" terminate in practice is not the loop but a **stop rule + scope freeze**: bounded rounds (the M3d rework breaker already exists), escalation to a human on non-convergence, and a frozen substrate during the clean round. Without those, the redirect is the same whack-a-mole with better rhetoric. Convergence is a heuristic exit condition, not a fixpoint in the mathematical sense — call it that.

  **(b) Isn't the small gate just gates again?** Yes — and that's fine. The distinction that survives scrutiny is not declarative-vs-semantic; it's **check-the-occurrence vs. check-the-content**. A turnstile gate ("a screening artifact keyed to the *current* substrate hash exists, verdict typed, findings dispositioned, round counter within cap") is decidable in ~100 lines. This is the standard pattern everywhere: GitHub branch protection doesn't review code, it enforces that review *happened*; `-Werror` doesn't prove correctness, it enforces that the compiler *ran clean*. The swarm's sin was not being gates — it was being 12 gates × 3 phases with bespoke parsers each.

  **(c) What makes a clean round trustworthy?** Mostly nothing intrinsic. Counterexamples:
  - **CI retry-until-green** is a known anti-pattern: a clean run of a flaky suite is evidence of luck, not health. A semantic screener is a flaky oracle by construction.
  - **Security audits** never certify "clean"; they time-box and report residual risk. A clean round after N rounds is a *stopping rule*, not a proof. The design should say "residual risk accepted by a human" at the boundary, not "convergence is the pass condition."
  - **Asymmetric capability:** if the screener model ≤ the author model, clean rounds are noise. Mitigation that actually works: the clean round must come from a *different* screener (different provider/family) than the one whose findings were fixed — independence is already a UACP principle (`council-reviewer-independence`); wire it into the pass condition, don't leave it as taste.

  **(d) Non-determinism.** Two runs disagree → treat **disagreement itself as a finding** requiring adjudication, never majority-vote it away. This is how distributed consensus handles it: you don't average divergent states, you force them through the protocol. Where "run until clean" genuinely works in industry, the oracle is mechanical: fuzzing (crash = crash, coverage-guided, corpus persisted, crashes minimized), property testing (executable assertion + shrinker), type checkers (decidable, monotone fixpoint). In all of these the *oracle* is deterministic and only the *search* is semantic. UACP's screening has a semantic oracle — so it can borrow the loop shape but not the convergence guarantees. The honest import from fuzzing is: **persist the corpus** (findings registry → regression tests), so each found defect class becomes a deterministic check next time. That's how a semantic loop amortizes into deterministic floor over time. Nothing in the redirect says this; it should.

  ## 4. The real design, concretely

  Minimal mechanism, five pieces:

  1. **`substrate(run_id) -> (bytes, hash)`** — deterministic producer, already built: merge-base..HEAD diff + reality-run transcript. Keep.
  2. **`screen(substrate_hash, screener_id) -> artifact`** — one adversarial dispatch, neutral charge + lenses, writable scratch, typed output `{substrate_hash, verdict: clean|findings|cannot_verify, findings[], screener}`. Semantic. Keep `grounding-screening.md` as-is; it's the best artifact on the branch.
  3. **The turnstile gate (the only gate)** — VERIFY crossing blocks unless: (i) a screening artifact exists whose `substrate_hash == current_hash`; (ii) verdict == `clean`; (iii) that clean round's screener ≠ the screener of any findings-round on the prior hash (independence); (iv) all prior findings dispositioned with resolving fix pointers; (v) round count < cap, else escalate-to-human (never silent-pass, never loop). All five checks are mechanical. Target: one file, <150 lines, one phase. Severity starts at warn, promotes to block only after N clean dogfood runs — the config-gated severity ladder was a good idea, applied too early.
  4. **Findings → corpus** — every confirmed finding spawns a deterministic regression check (test, lint rule, schema constraint) where expressible. This is the only mechanism that makes the loop *cheaper over time* instead of a perpetual semantic tax.
  5. **Scope freeze during a round** — fixes land, hash changes, *full* substrate re-screened (not delta-only; delta screening is what let sibling defects slip). Batch reviewer findings per round; no intra-round fix-forward.

  Determinism lives in: hashing, artifact existence, hash equality, verdict typing, disposition resolution, round counting, screener-identity inequality. Semantic judgment lives in: the read, the lenses, the verdict, the adjudication of disagreements. Everything else — the six-substrate generalization, per-phase resolvers, disposition-loop machinery — waits until one instance has survived a clean round from a cross-provider screener.

  ## SHARPEST OBJECTION

  The redirect deletes the only thing that made the screening *non-skippable*, while keeping the screening — and calls that the fix. Strip the rhetoric and the surviving design is: **substrate producer + semantic read + one turnstile gate**. That is the swarm's architecture, shrunk to one instance. So the verdict's headline ("verify is RUN, not built; gates don't verify") is contradicted by its own redirect (step 4: a gate enforces the run), and the non-convergence it cites as proof is equally well — better — explained by "7k lines, three phases at once, fix-forward churn, no scope freeze." The true lesson is *converge one instance before instantiating six*, which is a sequencing failure Claude is rebranding as a paradigm discovery. The risk: the rebrand licenses deleting enforcement machinery and replacing it with a prompt convention ("run a screening") — i.e., re-opening the exact self-attestation hole the whole bundle existed to close. If the rebuild ships the loop without the turnstile gate from step 4, it will have regressed to pre-#172 verify-theater with better documentation.

Help turn ideas into fully formed designs and specs through natural collaborative dialogue.

- Catch bugs and edge cases
- Ensure code maintainability
- Share knowledge across team
- Enforce coding standards

- Show off knowledge

**Good Feedback is:**

- Specific and actionable
- Educational, not judgmental

- Balanced (praise good work too)

**What Not to Review Manually:**

## Common Pitfalls

- **Perfectionism**: Blocking PRs for minor style preferences
- **Scope Creep**: "While you're at it, can you also..."
- **Inconsistency**: Different standards for different people
- **Delayed Reviews**: Letting PRs sit for days
- **Ghosting**: Requesting changes then disappearing
- **Rubber Stamping**: Approving without actually reviewing
- **Bike Shedding**: Debating trivial details extensively

5. Add regression tests for every discovered structural defect.
6. Promote from warn to block only after several stable dogfood runs.

That might have made the implementation converge. It would not prove semantic correctness, but it would distinguish design failure from oversized, churn-heavy implementation.

3. Attack the redirect

(a) The RUN-loop can also fail to converge.

There is no well-founded decreasing measure. A semantic screener can find a new defect class after every fix, miss defects indefinitely, or introduce no findings because it is weaker than the author. A round cap and human escalation are termination controls, not convergence.

The loop must never convert “cap reached” into pass. Its terminal states need to be:

`clean`, `blocked`, or `escalated`

—not “probably clean.”

(b) The small gate is still a gate.

That is not inherently bad. The defensible distinction is:

- semantic screening judges content;
- the gate enforces occurrence, binding, provenance, and state transition.

But “small” is not automatic. The existing defects were in supposedly mechanical machinery: run binding, two-root resolution, schema validation, envelope handling, traversal, and fail-open behavior. A generic gate can still become a large policy interpreter.

It is only genuinely small if it does not interpret semantic findings and does not trust caller-supplied fields such as `screener_id` or `verdict`. It needs an execution receipt from a trusted runtime boundary, not merely JSON claiming that an external reviewer ran.

(c) A clean round is weak negative evidence.

Nothing intrinsic distinguishes “no finding” from “the screener missed it.” Cross-provider review reduces correlated blindness but does not establish independence. A weaker model, a tired reviewer, an incomplete lens, or a malformed reality transcript can all produce a clean artifact.

The useful controls are:

- versioned lenses with required coverage fields;
- immutable tool and model provenance;
- independent screening for high-risk changes;
- a persistent regression corpus;
- full-substrate re-screening after fixes;
- fail-closed `cannot_verify`;
- human escalation on disagreement or the round cap.

These improve confidence. They do not turn a clean round into a proof.

(d) Non-determinism needs conservative resolution.

Two screeners disagreeing should not be averaged or majority-voted away. A plausible finding from either screener should block until it is rejected, fixed, or adjudicated. A clean result from one screener cannot erase a finding from another.

The analogies are limited:

- Type checking works because the oracle is deterministic and decidable over a defined subset.
- Property testing works because the property is an executable oracle; repeated sampling remains probabilistic.
- Fuzzing benefits from deterministic crash oracles, corpus persistence, and minimization, but “no crash observed” is not a proof.
- CI retry-until-green is a direct counterexample: if a flaky test has any nonzero chance of passing, retries eventually manufacture a green result.
- Distributed consensus does not certify safety by repeated clean observations; it uses quorum and invariants. Under asynchronous failure, FLP shows that termination cannot simply be assumed.

“Run until clean” is therefore a useful workflow heuristic, not a mathematical fixpoint.

4. The real design

Use one generic mechanism with phase-specific substrate producers.

Pieces:

1. `SubstrateProducer`

Produces an immutable object:

`{run_id, phase, snapshot_id, evidence_refs, substrate_hash}`

The reality-run evidence must be host-captured or otherwise authenticated; an agent-pasted transcript is another declaration.

2. `ScreeningRunner`

Invokes the external screener against the exact substrate and versioned lens bundle. It owns the loop, not the kernel.

3. `ScreeningArtifact`

A governed, immutable artifact containing:

`{run_id, phase, substrate_hash, lens_version, execution_receipt, verdict, findings, parent_screening_id}`

The execution receipt must establish which runtime, model/provider, prompt/lens version, and tools actually ran. A free-form `screener_id` is insufficient.

4. `FindingLedger`

Findings are immutable records. Each must be fixed, rejected with rationale, or escalated. Confirmed findings should become deterministic regression checks where possible.

5. `FixpointTurnstile`

The only semantic-adjacent gate checks:

- current substrate hash equals the screened hash;
- run and phase bindings are valid;
- the screening execution receipt is authorized;
- the artifact schema and lens coverage are valid;
- verdict is `clean`;
- no finding remains unresolved;
- `cannot_verify` is impossible to finalize;
- the round/time cap was not exceeded.

Any code or evidence change produces a new hash and invalidates the old clean result. Re-screen the full final substrate; delta-focused screening may supplement it but cannot replace it.

The state machine is:

`produce → screen → findings? → fix → new substrate → screen`

A clean result becomes passable only when the required independence policy is satisfied. A disagreement or cap becomes escalation, never success.

Determinism belongs in hashing, artifact validation, authorization, state transitions, disposition status, and caps. Semantic judgment belongs in the screening and adjudication. Use one generic `uacp.screening` contract with a phase/subject registry; do not create a separate validator swarm for every phase.

SHARPEST OBJECTION

An authorized but weaker screener can inspect a genuinely defective final substrate, return `clean`, and satisfy every hash, schema, disposition, and round-count check. The turnstile proves that a screening occurred over the current bytes; it cannot prove that the screening was competent or that the code is correct. Without an independent execution authority and explicit escalation for uncertainty, the redirect recreates verify-theater with better metadata.

Findings are immutable records. Each must be fixed, rejected with rationale, or escalated. Confirmed findings should become deterministic regression checks where possible.

5. `FixpointTurnstile`

The only semantic-adjacent gate checks:

- current substrate hash equals the screened hash;
- run and phase bindings are valid;
- the screening execution receipt is authorized;
- the artifact schema and lens coverage are valid;
- verdict is `clean`;
- no finding remains unresolved;
- `cannot_verify` is impossible to finalize;
- the round/time cap was not exceeded.

Any code or evidence change produces a new hash and invalidates the old clean result. Re-screen the full final substrate; delta-focused screening may supplement it but cannot replace it.

The state machine is:

`produce → screen → findings? → fix → new substrate → screen`

A clean result becomes passable only when the required independence policy is satisfied. A disagreement or cap becomes escalation, never success.

Determinism belongs in hashing, artifact validation, authorization, state transitions, disposition status, and caps. Semantic judgment belongs in the screening and adjudication. Use one generic `uacp.screening` contract with a phase/subject registry; do not create a separate validator swarm for every phase.

SHARPEST OBJECTION

An authorized but weaker screener can inspect a genuinely defective final substrate, return `clean`, and satisfy every hash, schema, disposition, and round-count check. The turnstile proves that a screening occurred over the current bytes; it cannot prove that the screening was competent or that the code is correct. Without an independent execution authority and explicit escalation for uncertainty, the redirect recreates verify-theater with better metadata.
